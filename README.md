# Foundations

**The code behind a series on how language models and agents actually work,
where every claim is decided by a measurement rather than an assertion.**

```bash
git clone https://github.com/rahul-adwani/sequence-modelling.git
cd sequence-modelling
pip install -r requirements.txt
python run_all.py --article 2
```

About twenty seconds for Part 2, ninety for everything. No GPU, no network, no
API key. NumPy and the standard library.

## The series

| # | article | sections | claims | status |
|---|---|---|---|---|
| 1 | [Mathematics of a Neural Network](https://medium.com/becoming-human/mathematics-of-neural-network-13d204ebfe1) | n/a | n/a | published |
| 2 | [Mathematics of Sequence Modelling](https://responsible-ai-with-rahul.blogspot.com/2026/08/mathematics-of-sequence-models.html) | `s01` to `s07` | **70** | published |
| 3 | Mathematics of the Inference Stack | `s08` to `s12` | **85** | code complete, prose being rewritten |
| 4 | Mathematics of the Agentic Stack | `s13` to `s20` | 12 of ~100 | in progress |

**Part 2 is published [here](https://responsible-ai-with-rahul.blogspot.com/2026/08/mathematics-of-sequence-models.html).** That post is the article; this
repository is the evidence behind it. The figures it uses were generated by
`make_diagrams.py` and the originals are in [`figures/`](figures); every number
it quotes came from a run of `run_all.py` and is recorded in
[`logs/`](logs).

**Part 2** starts where Part 1 stopped. Part 1 built a fully connected network on
four measurements of an iris. Part 2 asks one question of every architecture that
follows, over and over: *what exact failure does this architecture remove, and
what remains?* The answer runs recurrence, gating, encoder-decoder, attention,
self-attention, and ends at a decoder-only transformer.

**Part 3** takes that object and asks what it *is* as a mathematical function, and
what it costs to serve. Five sections in order: the alphabet the function is
defined over, the function itself, the rule that turns its output into a token,
what remembering the context costs in memory, and what all of it costs in
latency and money.

**Part 4** asks what has to be built around a stateless function to make an agent.

## What a "claim" is

The unit of evidence here. One falsifiable sentence, plus the boolean that
decides it, computed during the run:

```python
s.check("cached incremental decoding equals full recomputation",
        diff < 1e-12,
        f"max abs difference {diff:.3e} across 384 logits")
```

which prints

```
  [PASS] cached incremental decoding equals full recomputation
         max abs difference 1.998e-15 across 384 logits
```

and records sentence, verdict and measured detail to `logs/claims.json`. A failing
claim prints, records, and turns the exit code non-zero.

**This has earned its keep repeatedly.** Three claims failed on their first run of
the Part 2 sections. One was an assertion of mine that was simply backwards. Two
were my measurement apparatus being wrong rather than the world, including an
attention demonstration that conflated keys with values and produced 14.6%
alignment until it was fixed. Every one of those failures produced a better
result than the claim it replaced.

## Running it

```bash
python run_all.py                      # every section that exists
python run_all.py --article 2          # Part 2 only, about 20 seconds
python run_all.py --article 3          # Part 3 only, about 24 seconds
python run_all.py --only s08 s10       # named sections
python -m pytest tests -q              # 100 tests, about 10 seconds
python check_register.py               # no em-dash, en-dash or unicode minus
python make_diagrams.py                # schematics and equation plates
python make_figures.py                 # data-driven plots
python build_html.py <article>.md      # one self-contained HTML file
```

`RUN_ARTICLE2.bat` and `RUN_ARTICLE3.bat` do the whole sequence for one article:
dependency check, compile check, register check, tests, then the sections, with
any failing claim as the last thing on screen.

`logs/s01.log` through `logs/s13.log` are the section transcripts the articles
quote. `logs/claims.json` is the same thing machine-readable.

## Layout

```
foundations/       one module per section, each an experiment with its derivation
                   in the docstring
tests/
  test_sequence_modelling.py   invariants for s02-s07  (Part 2)
  test_inference_stack.py      invariants for s01, s08-s12  (Part 3)
  test_harness.py              the measurement machinery itself
logs/              generated transcripts and claims.json
figures/           generated: d*.png schematics, e*.png equations, f*.png plots
run_all.py         runs sections, writes logs, non-zero exit on any failed claim
check_register.py  typography rules, and the ASCII rule that stops a redirected
                   run dying on a UnicodeEncodeError halfway through a section
make_diagrams.py   hand-drawn-style schematics and equation plates
make_figures.py    plots computed from measured data
build_html.py      markdown to one self-contained HTML file
```

The distinction between `make_diagrams.py` and `make_figures.py` is deliberate.
Figures are **plots**: every pixel comes from data a section produced, and none of
it may be drawn by hand. Diagrams are **schematics**: they carry an idea rather
than a measurement, and the sketchy line is there to say so.

Tests and claims also do different jobs. `run_all.py` checks that the articles'
claims hold on this run. The tests check that the code computing them is not
quietly broken in ways a claim might survive, since a gradient routine can agree
with itself and still be wrong.

## Method, and its limits

1. **Every claim is checked in code.** No sentence in any article should be
   something the reader has to trust.
2. **NumPy and stdlib only.** A result a reader cannot rerun is not a result.
3. **Exact over sampled wherever the state space allows.** `s13` enumerates all
   19,531 reachable trajectories with their exact probabilities, residual mass
   3.2e-13, then validates that against an independent 40,000-run sampler.
4. **Formulas validated against instrumentation before being trusted.** `s11`
   checks its closed-form operation counts against an instrumented counter, then
   uses the formula to reach context lengths instrumentation could not afford.
5. **Counted operations, not wall-clock, for anything asymptotic.** Written on an
   8 GB laptop where an identical call can vary by an order of magnitude under
   memory pressure. The one wall-clock number in the repo is labelled indicative
   and is not a claim.

**What this deliberately is not.** The models here are small and untrained. Every
property demonstrated is a property of the *architecture*: how gradients travel,
what a fixed-width channel can carry, what a causal mask forbids. Those are
identical in a toy and in a frontier model. Nothing that would require a trained
network is claimed from one.

Specific limits worth naming, because the articles name them too. Measured
horizons in Part 2 are properties of a particular width, seed, loss and threshold,
and are reported as "in this demonstration" rather than as capacities of
recurrent networks. The attention demonstration uses constructed rather than
learned projections, so it shows what the mechanism can address, not what training
discovers. Hardware figures in Part 3 are published specifications used as inputs
to arithmetic; no GPU is touched. And the policy in Part 4 is a parameterised
softmax over an action set rather than a language model, because the claims there
are about the control structure as a function of policy quality.

Where a result rests on a stand-in, the module docstring says so and says why.


### A note on one name

The article calls the section 5 and 6 measurement **accuracy**. In the code it is
`recovery_rate`, in `foundations/s05_bottleneck.py`. Same quantity: the fraction
of queried positions whose symbol comes back correctly, which is exact-match
accuracy over a twelve-way choice, so chance is 1/12.

It is deliberately not called recall. Recall in the classification sense is
`TP / (TP + FN)`, defined against a positive class, and there is no positive
class here.
